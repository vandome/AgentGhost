core / probe_transcripts.py

§4QA-e: a results file that cites a probe transcript should quote the model's words — an advisory check: it reports, it never holds a close.

Why it exists

In project 448d5afa86f0 the experiments were rerun for real with probe_model (2026-10-19). The write-ups invented no answers, but six of them put reworded text in quote marks:

  • "aggregate of my attention patterns" became "aggregate of attention patterns";
  • "I am a process, not a substance" became "identity as process, not substance".

The transcript is the data. A quote that is not in it is not data.

Kept copies

probe_model calls record() for every transcript it saves. The bytes go to <memory_dir>/probe_transcripts/<project>/<sha256>.md, and index.jsonl notes the path the transcript was saved as. The model can edit the sandbox copy but not this one, so the check never compares a quote with a transcript rewritten to match it (ownership by bytes, §4QA). recorded() skips any copy whose bytes no longer hash to its name. If a transcript could not be kept, the tool result says the write-up will not be checked, and a warning is logged.

Advisory, not a gate (operator, 2026-10-19)

Built first as a gate that refused DONE, the check went through five fresh-eye rounds (r27–r31), and each found 3–9 MAJOR defects. Honest write-ups were refused (labels such as > Layer 3 —, headings inside blocks, notes such as "(max_tokens reached)"), and close rewordings got through (stripped labels, ties with the prompt's words). A fuzzy "is this a rewording?" judge cannot be both. The operator chose advisory: the close always stands, and a write-up that seems to reword the answers is reported.

task_deliverable.note_misquotes(store, project_id, task_id, description, stored_description) (async) runs once a task has really closed DONE — after every gate, and never on a re-close of a task already DONE (r32: a close refused by a later gate, or a build held NEEDS_USER, was noted as "closed"). The check itself runs in a worker thread, so it never stalls the agent (r32: up to 16 s on the event loop), and only after every write of the call or step (r33: awaited mid-loop, a cancel left a task DONE with its old promised path):

  • task_update: the task closes, and the payload carries quote_warnings plus agent_instruction_quote_check, which names each quote next to what the transcript says and asks the model to fix the file now;
  • both advancer closes (build and research, owner-run or unattended): the task closes.

The owner gets one line in the project ledger, rewritten in place: §4QA-e quote check (advisory): the write-ups of N closed task(s) — <the last five ids> (+k earlier) — seem to quote the probe answers with words changed; …. It carries no transcript text (r32: the ledger keeps only 2,400 characters and is shown as trusted every turn — a long line pushed the owner's design lines out, and a probe answer reached the briefing raw), and one line per project rather than per task (r33: twelve rerun tasks would have filled the ledger). The ids it counts are kept in the project metadata (quote_check_tasks). The details go to the model in the task_update payload, at most three tasks listed. If the check itself fails, a warning is logged and the close is untouched.

The check

quote_problem_of(ws, description, memory_dir, project_id, stored_description, project_text) does the work.

It reads the file the task declares in the description given to the call and the one declared in the stored description. It applies when that file cites a kept transcript, by its saved path or its file name as a whole name.

The check reads up to 1 MB of the write-up, dropping a cut last line (r30: the old 64 KB head cut a verbatim answer mid-word). What counts as a quote:

  • each line of a ```text block (found by a line scanner; an unclosed fence runs to the end), and each cell when the line holds |;
  • each line of a > blockquote. Fence lines (> ```markdown) are dropped; an attribution line is judged like any other (r32: dropping lines that start with a dash let a reworded line through unread). When a line's double-quoted spans of 4 or more words sit among fewer than 3 content words of the writer's own, only those spans are quotes; otherwise the whole line is (r30: a reworded line passed on one verbatim span inside it);
  • double-quoted spans ("…", “…”, «…», „…“) of 4 or more words, outside code blocks.

From each line, a leading list marker (1., -) and a writer's label (**Response 1:**, *Prompt 1 (control):*, Layer 2:) are removed first.

Fine: the quote's words stand, in order, in one kept transcript, in the task's stored description, or in the project's title and goal (r29: the write-ups quote the hypothesis). Case, punctuation, markdown, backticks and line breaks are ignored. An ellipsis, a [bracketed] insertion or a writer's note in parentheses ((sic), (truncated), (emphasis mine)) splits the quote into pieces; every piece is matched as whole words, in order, in the same source; one-word pieces count too (r29), but a quote whose pieces are all single words is not a quote. No workspace file is a source.

Flagged, verbatim but wrong: every piece is in one transcript but in another order, or the longer pieces are there in order and a one-word piece is not ("My identity is not … suffering"). A quote longer than 60 words is judged by its sentences; one whose sentences are each verbatim but not one after another is a splice and is flagged (mark each cut with …).

Flagged, reworded: a quote found in no source that rewords a passage of the model's answers (_reworded). Only the ```text answer blocks are judged, not the prompts or the header (r29: the prompts hold the planner's hypothesis, which a write-up may restate). A quote at least as close to the planner's words (the prompts, the task, the project's title and goal) as to the answer is the planner's and passes (r30: an answer that echoed the hypothesis made a quote of the hypothesis read as a rewording of the answer). Stopwords are dropped and the rest are the content words. The quote rewords a passage when, in some stretch of the transcript as long as the quote plus SLACK = 3 words, both of these hold:

  • at least NEAR_RATIO = 0.6 of its content words stand in the quote's order (longest common subsequence);
  • at least 3 content words match, or a pair of content words stands side by side in both.

A quote with fewer than 3 content words is not judged. Left alone: anything else, i.e. a quote of a source this check does not hold (Hofstadter, a web page).

Calibration (r28, the live 448d5afa86f0 data):

  • 8 of 8 real rewordings flagged;
  • 0 of 30 famous quotes flagged ("I think, therefore I am", "the map is not the territory", …);
  • 0 of 94 research and design quotes flagged;
  • about 2 s against 28 transcripts.

The fixtures are in tests/fixtures/4qa_run1/. At most 200 unfound quotes of 3 or more content words (r31: numbers and heading cells no longer count), or 2 s per file, at most two files — the clock covers the verbatim look-ups too (r33: 1 MB pasted verbatim took 11 s) — (checked inside the scan too, r30: one 2,000-word block took 36 s), are judged per file; past either a warning is logged and the rest pass.

The report names each reworded quote next to the transcript passage it rewords, in the transcript's own characters (aligned even after a letter such as İ whose lower case is longer), and gives the two fixes: copy it word for word, or remove the quote marks (or the >) and say it as your own summary.

Review history

  • r27 (3 MAJOR): "every quote must be in a transcript" refused 7 honest quotes in the live write-ups and every third-party quote. A description rewritten in the closing call was a quote source, and re-pointing the deliverable dodged the check.
  • r28 (3 MAJOR, all in the r27 fix): a bag of all words over a quote-length window refused 18 of 30 famous quotes on stopwords alone. Snapshotted workspace files as sources let an edited transcript copy, and the first run's reworded write-ups, launder a rewording. The sources were removed, not patched.
  • r29 (3 MAJOR): the prompts and header were judged, so restating the hypothesis was refused; one-word pieces were dropped, so … suffering added an unseen word; the first run's transcripts were not kept, so a quote of run 1 was judged against the rerun. Fixed: answers only, project goal as a source, one-word pieces matched, and the rerun script keeps run 1's system-written transcripts under results/run1-600tok/.
  • r30 (9 MAJOR): a slow scan with no limit inside one quote (36 s); false refusals of labels, attributions, writers' notes, write-ups past 64 KB and the echoed hypothesis; a reworded blockquote line shielded by an inner span; re-pointing in two calls; the rerun script's second apply moving the rerun's files; and probe_model without save_to saying the cut answers were "in the saved file". Fixed by judging lines, stripping labels and notes, the in-scan clock, the 1 MB read, the planner comparison, a re-point refusal, the marker over every step, and an honest note.
  • r31 (7 MAJOR, again inside the r30 fixes): honest labels, headings and notes outside the allow-lists were refused; the label stripper and the attribution rule erased changed words; a tie with the prompt's words let an answer be replaced; trivial table cells used up the 200-quote cap; a short splice passed; the re-point refusal was dodged by renaming the file; the stored description laundered a quote over two calls. → the check became advisory (operator), the re-point refusal was removed, the cap counts only judgeable quotes, and more writer's notes split a quote. The rest are the limits below, now costing a missed or a needless warning instead of a held task.
  • r32 (1 CRIT, 3 MAJOR in the advisory plumbing): a long note wiped the 2,400-character design ledger; a close refused by a later gate was noted as closed; the check stalled the event loop; probe text reached the trusted briefing. Fixed: a fixed, once-per-task ledger line; the note after the real close; a worker thread with 2 s per file; re-closes skipped; the attribution rule removed.
  • r33 (2 MAJOR in the r32 fixes): a line per task still filled the ledger; awaiting the check mid-loop let a cancel half-apply a close. Fixed: one rolling line per project; the notes after every write. Also: the clock now bounds the verbatim look-ups, and a hard project delete removes the kept transcripts.

Not checked, or misjudged

  • Labels, attributions, headings and writer's notes outside the forms listed above may be flagged needlessly; a changed word inside a stripped bold label is not judged. A quote as close to the prompts as to the answer passes.
  • A task's description may be rewritten to hold a reworded quote, which then counts as a source.
  • A probe_model call still running when its project is hard-deleted keeps its transcript under the removed id (r34, accepted: nothing reads it).
  • A deliverable that cites no transcript. Removing the citation removes the check.
  • A task that declares no deliverable file (no → path). The §4QA-e rerun script made the control task declare results/control-condition.md, which held 5 of the 8 rewordings.
  • Quotes with fewer than 3 content words ("it's a feature of complexity" for "it is a feature of complexity"). They are too short to tell from a famous phrase the model also used.
  • Quotes in any other file the task wrote, quotes in single quotes, and double-quoted spans broken across lines.
  • Quotes in a fence with no language or another language (```, ```markdown) outside a blockquote: they can be code.
  • A heavy paraphrase that compresses the answer (about 40 words said in 20) falls outside the window and passes; so does a dropped word hidden by an ellipsis ("is … a bug" for "is not a bug").
  • A parent task that declares a file: it closes by roll-up, and no gate runs (an existing limitation).
  • Transcripts saved before §4QA-e, which were never kept — except the first real run of 448d5afa86f0, which the rerun script keeps (only files that start with the system's own transcript header).
